> 対応仕様: `docs/spec.md` v3.0 / 2026-05-12
> 版数: v1.0 / 2026-05-13

---

## 0. 本書の位置づけ

本書は `docs/spec.md` v3.0 に定義された要件・画面・ロジックに対する**テスト仕様**を定義する。
実装側のテストコード(`src/**/__tests__/*` および `e2e/*.spec.ts`)は本書のテストケースをカバーすることを目指す。

### 0.1 対象範囲

- Phase 0〜3 で実装する機能(`docs/spec.md` 7節)
- Phase 4(AWS デプロイ)のインフラテストは本書の対象外(別途 Terraform plan/apply 検証で実施)
- Phase 5(Pending 機能)は対象外

### 0.2 対象外

- パフォーマンス負荷試験(2名利用前提のため除外)
- マルチブラウザ互換テストの自動化(`docs/spec.md` 9節の主要ブラウザは手動確認)
- セキュリティ侵入テスト(招待制 + 内部利用前提)

## 1. テスト戦略

### 1.1 テストピラミッド

| 層         | ツール                     | 想定比率 | 観点                                                       |
| ---------- | -------------------------- | -------- | ---------------------------------------------------------- |
| 単体テスト | Vitest                     | 70%      | 計算ロジック、コンポーネント描画、Server Action の純粋部分 |
| 統合テスト | Vitest + Prisma(テスト DB) | 20%      | DB をまたぐ整合性、トランザクション、認可                  |
| E2E テスト | Playwright                 | 10%      | 主要ユーザーフロー(ログイン→閲覧→入力)                     |

### 1.2 「予兆検知」というプロダクト核に対するテスト方針

`docs/spec.md` 2.1 / 4 節の通り、本プロダクトの中核は**進捗計算と乖離検出**である。
このため進捗計算ロジック(`src/lib/progress.ts` 相当)・重み均等割り・ステータス判定・連鎖予測には**仕様書 4 節を一次ソースとした厳密なテーブル駆動テスト**を最優先で配置する(P0)。

### 1.3 優先度の定義

| Priority | 意味         | 判定基準                                                   |
| -------- | ------------ | ---------------------------------------------------------- |
| P0       | リリース必須 | 失敗するとプロダクト価値が成立しない(進捗計算、認証、認可) |
| P1       | リリース推奨 | UX を著しく損なう(画面表示、CRUD 基本動作)                 |
| P2       | 段階的整備   | エッジケース、視覚的な細部                                 |

## 2. テスト環境

### 2.1 単体・統合テスト

- **ランナー:** Vitest(`npm test` で一括実行、`npm run test:watch` で監視)
- **DB:** Prisma + テスト用 PostgreSQL(`compose.yaml` の `postgres` サービス、または CI 上の `services.postgres`)
- **時刻固定:** `vi.setSystemTime()` を使い、`docs/spec.md` 11 節サンプルデータの基準日に揃える
- **DB クリーン戦略:** 各テストで `beforeEach` にて `TRUNCATE ... CASCADE`、または Prisma の `$transaction` でロールバック

### 2.2 E2E テスト

- **ランナー:** Playwright(`e2e/*.spec.ts`)
- **対象環境:** Docker Compose で起動した `app + postgres`、もしくはローカル `npm run dev` + Docker `postgres`
- **シード:** `npm run db:seed` で投入される `admin@example.com` / `pm@example.com`(password: `password123`)を起点
- **ブラウザ:** Chromium(Playwright デフォルト)。Firefox/WebKit は `docs/spec.md` 9 節準拠で必要に応じて追加

### 2.3 CI

`.github/workflows/ci.yml` にて `lint → typecheck → test → build` の順で実行。
PR をマージするには全工程グリーンが必須。
