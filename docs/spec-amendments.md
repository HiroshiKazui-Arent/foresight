## M-01: 日報入力のチェックボックス化

### 背景

ToDo の進捗を 0–100% で入力する UI は過剰。完了/未完了の二値で十分とする。

### 修正内容

| 項目                    | 修正前                   | 修正後                       |
| ----------------------- | ------------------------ | ---------------------------- |
| I1 画面の入力           | 進捗% または完了チェック | **完了チェックボックスのみ** |
| `Todo.actualPct`        | 0–100 の Int             | **削除**                     |
| `Todo.completed`        | Boolean                  | これだけが進捗の表現         |
| `DailyReport.actualPct` | 0–100 の Int             | **削除**                     |
| `DailyReport.completed` | Boolean                  | これだけが記録対象           |

### 進捗計算への影響(`spec.md` 4.2 を上書き)

```
Task実績% = Σ(completed=true の ToDo の重み) / Σ(全 ToDo の重み) × 100
```

`actualPct` ベースの計算式は完全に廃止する。重み合計が常に 100 とは限らないテストフィクスチャを許容するため `totalWeight` での正規化を行う(実運用では `redistributeWeights` により合計 100 が保証される)。
Milestone / Project の集計式は `spec.md` 4.2 のまま(配下の実績% に重み付き合計)。

### Q-01 の自動解消

`docs/test-spec.md` Q-01「`completed` と `actualPct` の優先関係」は、`actualPct` 自体が削除されるため不要となり、本修正でクローズする。

## M-02: ToDo セットリストの自動投入

### 背景

Task 作成のたびに同じ ToDo(画面設計、DB 設計、…)を手入力するのは非効率。Task 作成時にデフォルトの ToDo セットを自動投入する仕組みを追加する。

### データモデル追加

```prisma
model TodoTemplate {
  id        String   @id @default(cuid())
  name      String
  order     Int      // 自動投入時の順序
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([order])
}
```

### デフォルト ToDo セットリスト(seeder で投入)

| order | name               |
| ----- | ------------------ |
| 1     | 画面設計           |
| 2     | データベース設計   |
| 3     | バックエンド開発   |
| 4     | フロントエンド開発 |
| 5     | テストコードの実装 |
| 6     | テスト・レビュー   |

`prisma/seed.ts` でこの 6 件を `TodoTemplate` に投入する。

「テスト・レビュー」は人による最低限の動作確認のみを指す。少人数開発のためコードレビューはボトルネック化を避ける目的で実施しない。

### 動作仕様

- Task 新規作成時、サーバー側で `TodoTemplate` を `order` 昇順で読み、Task 配下に `Todo` を一括作成する
- 自動作成された各 ToDo の期間は **Task の期間と同一** で初期化する(後で個別編集可)
- 自動作成された ToDo は後から個別削除可能
- 任意の ToDo を手動で追加可能(従来通り)
- 重み均等割り(`spec.md` 6.7)は自動投入後の状態に対しても適用される
- `TodoTemplate` 自体の編集 UI は Phase 1 では実装しない(seeder のみで管理。Phase 5 で UI 化を検討)
